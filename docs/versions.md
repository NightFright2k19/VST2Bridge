# Version history

What changed in each Autobuild release, newest first. Releases are numbered `r<N>` and can be downloaded from the [Releases](https://github.com/NightFright2k19/VST2Bridge/releases) page; the number in the patcher's file name tells you which one you have. Numbers in brackets are issues / pull requests.

| Release | Date | Changes |
|---|---|---|
| next | | Windows bridge: a plugin that opens a message box or dialog no longer freezes the host; the helper answers the host's calls while the dialog is open ([#30](https://github.com/NightFright2k19/VST2Bridge/issues/30)). |
| next | | Windows bridge: the mouse wheel no longer freezes the host. A wheel turn that the plugin did not use up was passed on to the host's window while the host waited for the helper (FL Studio with e.g. Pro-53 or Xphraze; [#30](https://github.com/NightFright2k19/VST2Bridge/issues/30)). |
| r20 | 2026-11-06 | Windows and Linux / macOS bridges: the speed-ups of r15 (polling for the helper's answer, MMCSS, the helper reading its audio socket directly, protocol version 3) are taken out again, so the bridges work as in r14. The cause was a rare race in the polling that could answer a plugin's callback to the host twice. `VST2BRIDGE_SPIN` no longer has any effect. |
| r18 | 2026-11-06 | New developer kit `VST2Bridge-DevKit-r<N>.zip` in each release (`x86_host` and `x64_host` folders with the bridge DLL and helper) and a guide for adding direct loading to a Windows VST2 host ([docs/host-integration.md](host-integration.md)). |
| r17 | 2026-11-05 | Internal: the tests also run the Linux CLAP with AddressSanitizer + UndefinedBehaviorSanitizer; the Linux / macOS bridge reads its "helper gone" flag atomically (no behaviour change). |
| r15 | 2026-11-05 | Linux / macOS: the helper's audio thread reads the bridge's signals from its socket directly, one thread wake-up less per audio block. |
| r15 | 2026-11-05 | Windows bridge: the audio thread now polls briefly for the helper's answer before it sleeps and the helper's audio thread uses MMCSS, so a `process` call returns sooner and uses less CPU with many instances (about a third faster in our Wine benchmark). `VST2BRIDGE_SPIN=0` turns the polling off. |
| r14 | 2026-11-05 | Windows VST2 hosts can open plugins by path with `VST2BridgeCreateA/W`, so they can reuse a single bridge DLL without generating one per plugin. |
| r13 | 2026-11-05 | Patcher: the search path now sits on the same line as the *Search in:* label instead of a few pixels lower. |
| r12 | 2026-11-05 | Patcher: the original plugins are never moved any more; the bridge files and the helper exe are written next to each plugin, in the folder it was found in. The patcher's own folder is both source and destination, so the `input` / `output` folders, the **Output folder** row with **Change…**, `--output` and the *name taken* status are gone ([#17](https://github.com/NightFright2k19/VST2Bridge/issues/17)). |
| r11 | 2026-11-05 | License: the project is now licensed under the LGPL v3 (was named GPL-3.0 in the README and the release notes); README and development notes have a license section. |
| r10 | 2026-11-05 | Patcher: plugin DLLs lying directly in the patcher's own folder are found as well (not only in `input` or an added folder); the bridges, helper files and the `output` folder are not mistaken for plugins. |
| r10 | 2026-11-05 | Patcher: the output folder can be chosen in the window (**Change…** next to *Output folder*); the choice is remembered for the next start. `--output` on the command line still wins. |
| r9 | 2026-11-05 | Patcher: the original plugins are no longer copied but moved from `input` (or an added folder) into `output`, so `input` is empty afterwards and `output` holds everything for the host: plugin, bridge files and helper exe. Plugins already in `output` are listed too, so their bridges can be refreshed. |
| r9 | 2026-11-05 | Patcher: new program icon (the one of the SXG-Create-NF patcher) for the Windows exe, the macOS app and the window on all systems. |
| r8 | 2026-11-05 | Patcher: plugins are searched only in the subfolder `input` next to the patcher (plus folders added with **Add folder…**); bridges are always written to the subfolder `output` (with a copy of the plugin and the helper); every plugin has a checkbox (all ticked at the start) to choose what is converted; Windows patcher: **Output format** (VST2 + CLAP, VST2 only, CLAP only) ([#9](https://github.com/NightFright2k19/VST2Bridge/issues/9)). `--cli` gets `--output` and `--format`. |
| r7 | 2026-11-05 | Sample rates: the bridge no longer converts sample rates or reads `vst2bridge.ini`; the plugin always gets the rate the host sets (VST2 and CLAP bridge, removes the r4 conversion) ([#10](https://github.com/NightFright2k19/VST2Bridge/issues/10)). |
| r6 | 2026-11-04 | Windows CLAP bridge: the VST2 bridge is built into the `.clap`, so it works on its own with the plugin and the helper exe (it no longer needs `<name>_x64.dll` next to it). The plugin is found by the `.clap` file name without `_x64` / `_x86`; a missing plugin is written to `%TEMP%\vst2bridge.log`. |
| r5 | 2026-11-04 | Linux and macOS (Apple Silicon and Intel): patchers for both systems that write CLAP bridges only (`<name>.clap` + the helper of the plugin's bitness); the CLAP runs the Windows plugin (32-bit or 64-bit) under Wine. The plugin's window is embedded on Linux (X11) and floating on macOS. The patcher updates itself on all three systems. |
| r4 | 2026-11-04 | Unusual sample rates: when the host runs at a rate other than 44.1 / 48 / 88.2 / 96 / 176.4 / 192 kHz (e.g. 32000 Hz), the plugin runs at 44100 Hz and the bridge converts audio and MIDI timing, so plugins like S-YXG50 keep the right pitch. `vst2bridge.ini` next to the plugin can set another rate or turn it off (VST2 and CLAP bridge). |
| r4 | 2026-11-04 | CLAP bridge: plugins that set no "synth" flag and do not answer `effCanDo` (old instruments such as S-YXG50) are now offered as instruments with a MIDI input; before, hosts like Woof! rejected them and fell back to the previous MIDI synth. |
| r3 | 2026-11-04 | CLAP bridges: next to every VST2 bridge the patcher also writes a CLAP bridge of the same name (`<name>_x64.clap` for 64-bit hosts, `<name>_x86.clap` for 32-bit hosts) with audio, MIDI, parameters, presets, latency and the plugin's window. Bridges written by r1 or r2 show as "update" and get their `.clap` with **Create bridges**. |
| r2 | 2026-11-04 | Patcher: the same 29 languages as the SXG-Create-NF patcher (was English and German only); the system language is chosen automatically, the menu at the top right switches it. |
| r1 | 2026-11-04 | First version (#1): the patcher finds 32-bit and 64-bit VST2 plugins and writes a bridge next to each (`<name>_x64.dll` for 64-bit hosts, `<name>_x86.dll` for 32-bit hosts). The bridge runs the plugin in a helper process and passes audio, MIDI and SysEx, parameters, presets (chunks), the plugin's own window and the plugin's calls to the host. |
